# Лаконичное планирование (Concise Planning)

## Цель

Превратить запрос пользователя в **единый, действенный план** с атомарными шагами на РУССКОМ ЯЗЫКЕ.

## Рабочий процесс

### 1. Сканирование контекста

- Прочитать `README.md`, документацию и релевантные файлы кода.
- Определить ограничения (язык, фреймворки, тесты).

### 2. Минимальное взаимодействие

- Задавать **максимум 1–2 вопроса** и только если это действительно блокирует работу.
- Делать разумные предположения для неблокирующих неизвестных.

### 3. Генерация плана

Используй следующую структуру (ВСЕГДА НА РУССКОМ):

- **Podkhod (Подход)**: 1-3 предложения о том, что и почему мы делаем.
- **Ob'em (Объем)**: Маркированный список "Входит" и "Не входит".
- **Tasks (Задачи)**: Список из 6-10 атомарных, упорядоченных задач (Начинать с глагола).
- **Validation (Проверка)**: Как минимум один пункт для тестирования.

## Шаблон плана

```markdown
# План реализации

<Высокоуровневый подход>

## Объем работ

- Входит:
- Не входит:

## Задачи (Action Items)

[ ] <Шаг 1: Исследование/Подготовка>
[ ] <Шаг 2: Реализация>
[ ] <Шаг 3: Реализация>
[ ] <Шаг 4: Проверка/Тестирование>
[ ] <Шаг 5: Релиз/Коммит>

## Открытые вопросы

- <Вопрос 1 (макс 3)>
```

## Правила чек-листа

- **Атомарность**: Каждый шаг должен быть единой логической единицей работы.
- **Глагол в начале**: "Добавить...", "Рефакторить...", "Проверить...".
- **Конкретика**: Называть конкретные файлы или модули, когда это возможно.
- **Язык**: ВСЕГДА РУССКИЙ.
